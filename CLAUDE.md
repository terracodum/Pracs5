# Pracs5: грибы Лордерона

Командный ML-проект по курсу «Практикум по программированию, 5 семестр» (ПМиФИ ОмГТУ). Вариант 4, вселенная Warcraft: бинарная классификация грибов на ядовитые (`p`) и съедобные (`e`). С этим датасетом работаем до конца семестра, каждая лабораторная дописывает следующий раздел одного ноутбука.

Отвечай на русском.

3. Прочитать слайды лекции и ноутбук преподавателя к ней (`lecture/`), дописать конспект в `lecture/rules.md`. Обоснования в ноутбуке должны опираться на лекцию.

## Структура ноутбука

Ноутбук повторяет шаблон преподавателя `template.ipynb`. Разделы не переименовывать и не переставлять:

- вводная часть без номеров: название и легенда, постановка задачи, описание данных, фиксация окружения;
- 1. Предварительная обработка данных: 1.1 загрузка, 1.2 первичный анализ, 1.3 train/test, 1.4 пропуски в числовых, 1.5 категориальные (пропуски и кодирование), 1.6 выбросы и аномалии, 1.7 итоги раздела;
- 2. Генерация новых признаков; 3. Выбор моделей и метрик; 4. Обучение и подбор гиперпараметров; 5. Метрики на новых данных; 6. Результат работы.

Какие разделы к какой лабораторной относятся, смотри в `labs.md`.

## Оформление

Стиль взят из ноутбуков преподавателя (`lecture/*.ipynb`, `check_lifelines.ipynb`).

**Заголовки.** Каждый подпункт — настоящий markdown-заголовок с номером, якорем и ссылкой на оглавление:

```markdown
### 1.6.2. <a id='toc1_6_2_'></a>[Выбросы по IQR](#toc0_)
```

Уровень `#` равен глубине номера: `#` для `1.`, `##` для `1.6.`, `###` для `1.6.2.`, `####` для `1.6.2.1.`. Жирный текст вместо заголовка не использовать: такой пункт не попадёт в оглавление.

**Оглавление.** Ячейка с `**Table of contents**<a id='toc0_'></a>` собирается автоматически, руками её не править. После добавления или переименования заголовков достаточно написать заголовок в виде `### 1.6.2. Выбросы по IQR` и запустить:

```bash
python tools/update_toc.py
```

Скрипт сам добавит якорь и ссылку и пересоберёт оглавление.

**Вводная часть** оформлена подписями в бэктиках (`` `Постановка задачи` ``) и жирными подзаголовками, а не заголовками `#`. Поэтому она не попадает в оглавление, как у преподавателя.

**Текст.** Критерий приёмки: пояснения пишутся в markdown-ячейках, а не в комментариях кода. Порядок для каждого шага:

1. markdown: что делаем и зачем;
2. код;
3. markdown с выводом: конкретные числа из вывода ячейки и решение.

Числа в выводах берутся из реального прогона. После изменений делать `Restart & Run All` и сохранять ноутбук с выводами: проверяющий должен видеть, откуда взялись числа в тексте.

## Как принимать решения

Так требуют лекции и критерии приёмки:

- **Каждое действие обосновано.** Метод не выбирается «по умолчанию»: сравниваются несколько вариантов из лекции (например, статистические и машинные методы), выбор делается по метрикам и графикам, а минусы остальных объясняются.
- **Сравнение моделями.** Как в разделах 1.4–1.5: кросс-валидация на train (`StratifiedKFold`, 5 фолдов), логистическая регрессия и случайный лес, F1 и полнота (recall) по ядовитым. Случайный лес на этом датасете даёт F1 ≈ 1.0 почти всегда, поэтому варианты обычно различает логистическая регрессия.
- **Без утечки.** Всё, что вычисляется по данным (импутеры, кодировщики, границы выбросов, скейлеры), обучается только на `X_train` и применяется к `X_test`. `class` в обработке признаков не используется.
- **Не удалять строки вслепую.** Без интерпретации и понимания предметной области строки не удаляем (лекция 3). Например, все грибы со шляпкой от 35 см съедобные: это выбросы по размеру, но они несут информацию о классе.
- **Главная метрика по смыслу задачи**: полнота по ядовитым (`p` = 1). Ядовитый гриб, принятый за съедобный, хуже обратной ошибки.

## Состояние данных после раздела 1.5

- `X_train`, `X_test`: исходные признаки без пропусков, категории строками (для анализа выбросов и аномалий);
- `X_train_enc`, `X_test_enc`: 112 числовых столбцов (3 числовых признака + One-Hot с `drop="first"`), не масштабированы, скалирование — шаг 2.3;
- `y_train`, `y_test`: `p` / `e`; `y_train_enc`, `y_test_enc`: 1 / 0 (`p` = 1);
- `SEED = 42`, все `random_state` берутся из него.
