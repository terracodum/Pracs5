## 1. Главный принцип

**Каждый шаг в работе нужно обосновывать.** Без обоснования работа превращается в чёрный ящик, и модели нельзя доверять. Обоснование нужно и для читаемости, и для воспроизводимости.

Цель проекта: получить **жизнеспособную, надёжную и понятную** модель.

Пять правил:
1. Решения принимать на основе статистики и графиков, а не «наугад».
2. Обосновывать выбор методов предобработки и моделей.
3. Уметь интерпретировать работу модели.
4. Не перебирать все варианты вслепую: это невозможно.
5. Писать так, чтобы работу можно было перезапустить с теми же параметрами.

## 2. Пайплайн (CRISP-DM)

**CRISP-DM**: стандартная методология жизненного цикла проекта, от бизнес-задачи до внедрения.

Этапы: Business Understanding → Data Understanding → Data Preparation → Modeling → Evaluation → Deployment.

| № | Шаг | Этап CRISP-DM |
|---|---|---|
| 0 | Описание задачи и признаков | Business & Data Understanding |
| 1 | Предварительная обработка данных | Data Preparation |
| 2 | Генерация новых признаков | Data Preparation |
| 3 | Выбор моделей и метрик качества | Modeling |
| 4 | Обучение, кросс-валидация, подбор гиперпараметров | Modeling |
| 5 | Предсказания на новых данных и метрики | Evaluation |

Каждая ML-задача уникальна, но базовый пайплайн по CRISP-DM можно использовать как шаблон.

### Шаг 0. Описание задачи и признаков

- [ ] Постановка задачи.
- [ ] Описание признакового пространства: входные и целевые признаки, ограничения на значения, зависимости прикладной области.
- [ ] Виртуальное окружение: импорт библиотек, `seed`, фиксация версий библиотек.
- [ ] В конце: содержание работы (table of content).

**Цель:** читатель понимает, зачем решается задача, а работу можно запустить с теми же параметрами.

### Шаг 1. Предварительная обработка данных

**Цель:** данные, на которых можно обучить baseline-модель.

## 4. Деление на train/test: типичные ошибки

| Ошибка | Что делать |
|---|---|
| Утечка информации | Сначала делить выборку, потом работать только с train и переносить результат на test |
| Игнорирование временной структуры | Данные из «будущего» не должны попадать в обучение |
| Нарушение баланса классов | Стратификация, например `stratify=...` |
| Слишком большой или маленький train/test | Контролировать объём выборки |

## 5. Пропущенные значения

Если в данных остались пропуски или необработанные категории, большинство моделей обучить не получится.

### 5.1. Четыре подхода

| Подход | Суть |
|---|---|
| Интерпретация | Заполнить по бизнес-правилам признакового пространства |
| Статистические | Заполнить значением, вычисленным по выборке (mean, median) |
| Машинные | Предсказать пропуск моделью (MICE, KNNImputer) |
| По соседям | Заполнение на основе соседних значений |

### 5.2. Интерпретация

- Категориальный признак: пропуск → отдельная категория, например `'NaN'`.
- Вещественный признак: пропуск → `0`, `-1` или `9999` (значение вне нормального диапазона).

### 5.3. Статистические методы

- Заполнение константой может сильно изменить распределение. Пример: в датасете из 10 000 записей 10% пропусков, заполненных средним, дают резкий пик посередине.
- Бывает, что невозможно выбрать лучшее значение среди кандидатов (например, mean против median на нормальном распределении).

**Как проверить статистический метод:**
1. Для каждого признака с пропусками определить множество значений для заполнения.
2. Для каждого значения построить две гистограммы (до и после заполнения) и посчитать **KL-дивергенцию**.
3. По виду распределений и дивергенции выбрать значение.

> **KL-дивергенция** показывает, насколько распределение q похоже на распределение p. Это число от 0 до бесконечности, и чем ближе оно к 0, тем больше распределения похожи.
>
> `D_KL(p||q) = Σ p(x) · ln( p(x) / q(x) )`

### 5.4. Машинные методы

Ловят нелинейные зависимости в структуре пропусков. Модель учится предсказывать столбцы с пропусками по остальным признакам, **без информации о целевом**.

- **MICE** (Multiple Imputation by Chained Equations): сначала пропуски заполняются случайно, потом итеративно уточняются моделью (например, random forest).
- **KNNImputer**: берётся среднее по ближайшим соседям.

### 5.5. Советы по пропускам

- Больше **50–70% пропусков** в признаке → считать его неинформативным и отбросить.
- Пропуск в **целевом значении** → строку удалить (таргет восстанавливать нельзя).
- Строки с **большой концентрацией пропусков** → удалить: после заполнения они станут аномальными (!).
- Пропусков в train-части нет, но признак может иметь их в test → **всё равно анализировать пропуски**.
- Не отдавать предпочтение только статистике или только моделям. **Заполнить обоими способами, потом сравнить метрики** обученных моделей.

## 6. Категориальные признаки

### 6.1. Виды

- Равнозначные категории.
- Категории с отношением порядка.
- Смешанные категории.

### 6.2. Кодировщики

| Метод | Плюсы | Минусы |
|---|---|---|
| **One-Hot** | Простота, интерпретируемость | Проклятие размерности при более чем 10 категориях |
| **Label** | Простота, не увеличивает размерность | Произвольный порядок, плохо для линейных моделей |
| **Target** | Учитывает связь с целью, сохраняет размерность | Риск переобучения, чувствительность к настройкам |

- **One-Hot**: на каждую категорию свой бинарный столбец (`color_red`, `color_blue`, …).
- **Label**: каждой категории свой номер (Apple → 1, Chicken → 2, …).
- **Target**: категория заменяется статистикой целевой переменной. Пример: Red, у которого таргет равен 1 в двух случаях из пяти, получает 0.4.

### 6.3. Стратегии Target Encoder

Через число таргетов со значением 1 (n₁) и 0 (n₀):

| Стратегия | Формула |
|---|---|
| Mean | `n₁ / (n₀ + n₁)` |
| Weight | `ln(n₁ / n₀) · 100` |
| Count | `n₁` |
| Diff | `n₁ − n₀` |

## 7. Выбросы и аномалии (лекция 3)

### 7.1. Определения

| Что | Определение | Уровень | Пример |
|---|---|---|---|
| **Выброс** | значение столбца, не похожее на подавляющее большинство значений | одно значение в одном признаке | `num_feature1 = 45664.8` среди значений 56–87 |
| **Аномалия** | объект (строка), не похожий на подавляющее большинство объектов | вся строка целиком | строка, где сразу несколько признаков на порядки больше обычного |

### 7.2. Инструменты

**Против выбросов:** ищут пороговые значения, внутри которых лежит большинство похожих значений признака.

| Метод | Как работает |
|---|---|
| Анализ распределений | гистограммы, функции плотности, «ящик с усами» по каждому признаку |
| **IQR** | `IQR = Q3 − Q1`; выброс, если значение `< Q1 − 1.5·IQR` или `> Q3 + 1.5·IQR` (Q1 и Q3 — 25-й и 75-й перцентили) |
| **Z-score** | `z = (x − μ) / σ`; выброс, если `|z|` больше порога |

**Против аномалий:** обучение без учителя, анализирует расположение объектов в признаковом пространстве.

| Метод | Как работает |
|---|---|
| **Isolation Forest** | строит много случайных деревьев, которые режут пространство случайными разбиениями; аномалию изолировать легко, поэтому путь до неё в дереве короткий |
| **One-class SVM** | строит гиперплоскость, отделяющую «нормальные» данные от начала координат; точки по другую сторону считаются аномалиями |
| **DBSCAN** | кластеризация по плотности (`eps` — радиус, `minPts` — минимум соседей); точки, не попавшие ни в один кластер (noise points), считаются аномалиями |

### 7.3. Как это делается в ноутбуке с занятия (`outliers.ipynb`)

1. Целевой столбец отбрасывают: выбросы и аномалии ищут только в признаках.
2. **Выбросы:**
   - строят гистограммы и «ящики с усами» по всем признакам;
   - для каждого метода (IQR, Z-score) объект помечается, если **хотя бы в одном** признаке значение вне границ (`np.any`);
   - выбросом считается объект, который пометили **все** методы (пересечение индексов, `np.intersect1d`).
3. **Аномалии:**
   - библиотека `pyod`: `IForest`, `OCSVM`;
   - аномалией считается объект, который пометили **все** алгоритмы (`np.all`);
   - для визуализации пространство понижают до 2D через `UMAP` и отмечают аномалии красными крестиками; доли показывают круговой диаграммой.
4. Найденные объекты удаляют из набора.

Алгоритмы подбирают так, чтобы они смотрели на **разную** пространственную информацию: так результат объективнее.

> В выложенном ноутбуке нет кода Z-score (используется переменная `outliers_objects_z_score_2`, но не определяется), порог по названию, видимо, 2. DBSCAN есть на слайдах, но не в коде.

### 7.4. Советы по выбросам и аномалиям

1. **Всегда начинать с графиков:** гистограммы, функции плотности, «ящик с усами». Они покажут выбросы внутри отдельных признаков.
2. Если выбросы видны, применять **IQR и Z-score вместе** и смотреть пересечение результатов. Выбросы нужно **интерпретировать (!)**.
3. После выбросов смотреть аномальные объекты, тоже **несколькими методами** со сравнением результатов, и тоже **интерпретировать (!)**.
4. Аномалии всегда можно визуализировать в двумерном пространстве.
5. **Без экспертной оценки и понимания предметной области удалять строки нельзя (!).**

Вывод из правил лекции 1 (на слайдах лекции 3 отдельно не сказано): границы IQR / Z-score и модели аномалий настраиваются только на train.

## 8. Генерация новых признаков и скалирование (лекция 4)

### 8.1. Что это и зачем

**Генерация признаков**: создание новых признаков (столбцов) на основе уже имеющихся значений.

Генерация может поднять итоговые метрики модели и исправить проблемы в данных. На слайде к «может увеличить» зачёркнута приписка «(а может не увеличить)»: прирост не гарантирован, поэтому каждый новый признак проверяется метриками.

Зачем:
1. **Точность.** Хорошо подобранные признаки помогают алгоритму понять структуру данных и закономерности.
2. **Сложные зависимости.** В исходных данных может не быть явных признаков, хорошо объясняющих целевую переменную.
3. **Упрощение модели.** Новые признаки могут упростить признаковое пространство.

### 8.2. Восемь подходов

| № | Подход | Суть | Пример со слайда |
|---|---|---|---|
| 1 | Свойства признакового пространства | формулы прикладной области (если они есть) | `feature3 = feature1 / feature2` |
| 2 | Арифметические операции | всевозможные комбинации признаков и операций `/`, `*`, `+`, `−` | столбцы `f1/f2`, `f1*f2`, `f1+f2`, `f1−f2` |
| 3 | Агрегация | для панельных данных (серия измерений одного объекта) и категориальных признаков: статистика признака внутри группы | `mean(i)`: среднее `feature` для `id = i` |
| 4 | Статистические преобразования (скалирование) | новое значение признака, чтобы улучшить распределение или снизить влияние выбросов и диспропорции величин | см. 8.3 |
| 5 | Функциональные преобразования | функция от признака, чтобы построить нелинейные связи | `ln(feature1)` |
| 6 | Интервальные признаки | вещественный признак как интервал значений (биннинг) | `int_f1`: `(0; 23]`, `(23; 43]`, `(43; 55]` |
| 7 | Сторонние данные | связь с другими датасетами по ключу, `join` | дописать `feature2` по `id` |
| 8 | Последовательные данные | паттерны и динамика: лаговые сдвиги, разности | `lag1`, `delta` |

### 8.3. Скалирование

| Метод | Формула | Что делает |
|---|---|---|
| **Стандартизация** | `x' = (x − x̄) / σ` | среднее 0, стандартное отклонение 1 |
| **MinMax** | `x' = (x − min) / (max − min)` | значения в `[0; 1]` |
| **Робастное** | `x' = (x − m) / IQR` | `m` — медиана; медиана и IQR мало зависят от выбросов |

Решение о скалировании принимается **на основе `df.describe()`**: смотреть на масштабы, средние, разброс и хвосты признаков.

В sklearn: `StandardScaler`, `MinMaxScaler`, `RobustScaler` (`fit` на train, `transform` на test).

### 8.4. Советы по генерации признаков

1. **Если есть возможность, всегда генерировать дополнительные признаки (!).** Неинформативные потом отсеиваются отбором после обучения модели.
2. **Все вспомогательные вычисления только на обучающей выборке и без целевых значений**, иначе утечка данных. Это касается скалирования, интервальных признаков, формул, агрегаций и временных рядов.
3. Формулы прикладной области помогают решить проблему **мультиколлинеарности**. Генерация признаков также решает проблемы слабых зависимостей в данных и диспропорции величин.

### 8.5. Что из этого применимо к нашим грибам

Наш вывод, на слайдах этого нет:

- числовых признаков три: `cap-diameter`, `stem-height`, `stem-width` (см) — с ними работают арифметика, формулы, функции и интервалы;
- формулы прикладной области: соотношения размеров гриба (например, `stem-height / cap-diameter`, `stem-width / cap-diameter`), условный объём; при делении учитывать нули (`stem-height` и `stem-width` бывают равны 0);
- функциональные: `ln(1 + x)` для правых хвостов размеров (на `describe()` максимум в 5–10 раз больше 75-го перцентиля);
- агрегация: среднее числового признака по категории (например, `cap-diameter` по `habitat`), считается только по `X_train`;
- интервальные: размер шляпки интервалами, границы по `X_train` (квантили или по смыслу, например «от 35 см»);
- сторонних и последовательных данных нет, подходы 7 и 8 не применяются;
- скалирование: размеры в разных масштабах (`stem-width` в среднем вдвое больше остальных) и с выбросами, которые мы не удаляли (1.6.8), поэтому кандидат `RobustScaler`; сравнить со `StandardScaler` и `MinMaxScaler` по кросс-валидации. Для случайного леса скалирование не важно, для логистической регрессии важно.
