# Шпаргалка по ML-проекту (лекции 1–2)

Практикум по программированию, 5 семестр. Свод правил и советов из лекций 1 и 2.

---

## 1. Главный принцип

**Каждый шаг в работе нужно обосновывать.** Без обоснования работа превращается в чёрный ящик, и модели нельзя доверять. Обоснование нужно и для читаемости, и для воспроизводимости.

Цель проекта: получить **жизнеспособную, надёжную и понятную** модель.

Пять правил:
1. Решения принимать на основе статистики и графиков, а не «наугад».
2. Обосновывать выбор методов предобработки и моделей.
3. Уметь интерпретировать работу модели.
4. Не перебирать все варианты вслепую: это невозможно.
5. Писать так, чтобы работу можно было перезапустить с теми же параметрами.

## 2. Пайплайн (CRISP-DM)

**CRISP-DM**: стандартная методология жизненного цикла проекта, от бизнес-задачи до внедрения.

Этапы: Business Understanding → Data Understanding → Data Preparation → Modeling → Evaluation → Deployment.

| № | Шаг | Этап CRISP-DM |
|---|---|---|
| 0 | Описание задачи и признаков | Business & Data Understanding |
| 1 | Предварительная обработка данных | Data Preparation |
| 2 | Генерация новых признаков | Data Preparation |
| 3 | Выбор моделей и метрик качества | Modeling |
| 4 | Обучение, кросс-валидация, подбор гиперпараметров | Modeling |
| 5 | Предсказания на новых данных и метрики | Evaluation |

Каждая ML-задача уникальна, но базовый пайплайн по CRISP-DM можно использовать как шаблон.

### Шаг 0. Описание задачи и признаков

- [ ] Постановка задачи.
- [ ] Описание признакового пространства: входные и целевые признаки, ограничения на значения, зависимости прикладной области.
- [ ] Виртуальное окружение: импорт библиотек, `seed`, фиксация версий библиотек.
- [ ] В конце: содержание работы (table of content).

**Цель:** читатель понимает, зачем решается задача, а работу можно запустить с теми же параметрами.

### Шаг 1. Предварительная обработка данных

- [ ] Загрузить данные, вывести, привести признаки к нужному типу (+ агрегация, парсинг дат, отбрасывание столбцов).
- [ ] Разделить выборку на train и test.
- [ ] Обработать пропуски.
- [ ] Закодировать категориальные признаки.
- [ ] Разобраться с выбросами и аномалиями.
- [ ] Устранить дисбаланс классов (для классификации).

**Цель:** данные, на которых можно обучить baseline-модель.

> **Baseline-модель**: наивная модель, обученная на базовом варианте обработанных данных. Нужна, чтобы проверять, помогает ли предобработка.

## 3. Загрузка датасета: чек-лист

- Проверить **кодировку** файла и **разделитель** (`.csv`, `.tsv`).
- Даты передавать в параметр `parse_dates`.
- Обязательно вывести фрагмент через `DataFrame.head()`: убедиться, что всё прочиталось.
- Проверить типы через `DataFrame.info()` и сверить с таблицей семантики признаков. Если типы не совпали, привести вручную.
- Для решения об отбрасывании категориального признака смотреть на его **семантику** и число уникальных значений (`Series.nunique()`).
- **Удалять признаки, которых не будет на момент прогноза.**
- Агрегаты разбивать на компоненты, если это не критично для задачи. Например, дату можно разбить на день, месяц и год, если задача не про временные ряды.
- Следить, чтобы во входных признаках **не было утечки данных**.

## 4. Деление на train/test: типичные ошибки

| Ошибка | Что делать |
|---|---|
| Утечка информации | Сначала делить выборку, потом работать только с train и переносить результат на test |
| Игнорирование временной структуры | Данные из «будущего» не должны попадать в обучение |
| Нарушение баланса классов | Стратификация, например `stratify=...` |
| Слишком большой или маленький train/test | Контролировать объём выборки |

## 5. Пропущенные значения

Если в данных остались пропуски или необработанные категории, большинство моделей обучить не получится.

### 5.1. Четыре подхода

| Подход | Суть |
|---|---|
| Интерпретация | Заполнить по бизнес-правилам признакового пространства |
| Статистические | Заполнить значением, вычисленным по выборке (mean, median) |
| Машинные | Предсказать пропуск моделью (MICE, KNNImputer) |
| По соседям | Заполнение на основе соседних значений |

### 5.2. Интерпретация

- Категориальный признак: пропуск → отдельная категория, например `'NaN'`.
- Вещественный признак: пропуск → `0`, `-1` или `9999` (значение вне нормального диапазона).

### 5.3. Статистические методы

- Заполнение константой может сильно изменить распределение. Пример: в датасете из 10 000 записей 10% пропусков, заполненных средним, дают резкий пик посередине.
- Бывает, что невозможно выбрать лучшее значение среди кандидатов (например, mean против median на нормальном распределении).

**Как проверить статистический метод:**
1. Для каждого признака с пропусками определить множество значений для заполнения.
2. Для каждого значения построить две гистограммы (до и после заполнения) и посчитать **KL-дивергенцию**.
3. По виду распределений и дивергенции выбрать значение.

> **KL-дивергенция** показывает, насколько распределение q похоже на распределение p. Это число от 0 до бесконечности, и чем ближе оно к 0, тем больше распределения похожи.
>
> `D_KL(p||q) = Σ p(x) · ln( p(x) / q(x) )`

### 5.4. Машинные методы

Ловят нелинейные зависимости в структуре пропусков. Модель учится предсказывать столбцы с пропусками по остальным признакам, **без информации о целевом**.

- **MICE** (Multiple Imputation by Chained Equations): сначала пропуски заполняются случайно, потом итеративно уточняются моделью (например, random forest).
- **KNNImputer**: берётся среднее по ближайшим соседям.

### 5.5. Советы по пропускам

- Больше **50–70% пропусков** в признаке → считать его неинформативным и отбросить.
- Пропуск в **целевом значении** → строку удалить (таргет восстанавливать нельзя).
- Строки с **большой концентрацией пропусков** → удалить: после заполнения они станут аномальными (!).
- Пропусков в train-части нет, но признак может иметь их в test → **всё равно анализировать пропуски**.
- Не отдавать предпочтение только статистике или только моделям. **Заполнить обоими способами, потом сравнить метрики** обученных моделей.

## 6. Категориальные признаки

### 6.1. Виды

- Равнозначные категории.
- Категории с отношением порядка.
- Смешанные категории.

### 6.2. Кодировщики

| Метод | Плюсы | Минусы |
|---|---|---|
| **One-Hot** | Простота, интерпретируемость | Проклятие размерности при более чем 10 категориях |
| **Label** | Простота, не увеличивает размерность | Произвольный порядок, плохо для линейных моделей |
| **Target** | Учитывает связь с целью, сохраняет размерность | Риск переобучения, чувствительность к настройкам |

- **One-Hot**: на каждую категорию свой бинарный столбец (`color_red`, `color_blue`, …).
- **Label**: каждой категории свой номер (Apple → 1, Chicken → 2, …).
- **Target**: категория заменяется статистикой целевой переменной. Пример: Red, у которого таргет равен 1 в двух случаях из пяти, получает 0.4.

### 6.3. Стратегии Target Encoder

Через число таргетов со значением 1 (n₁) и 0 (n₀):

| Стратегия | Формула |
|---|---|
| Mean | `n₁ / (n₀ + n₁)` |
| Weight | `ln(n₁ / n₀) · 100` |
| Count | `n₁` |
| Diff | `n₁ − n₀` |

## 7. Быстрый чек-лист «перед обучением»

- [ ] Окружение зафиксировано (seed, версии).
- [ ] Данные прочитаны верно (кодировка, разделитель, `head()`, `info()`).
- [ ] Типы признаков приведены, лишние признаки (в том числе недоступные на момент прогноза) удалены.
- [ ] Утечки нет.
- [ ] Выборка разделена на train/test **до** любых преобразований, при необходимости со стратификацией.
- [ ] Пропуски обработаны. Метод выбран и обоснован (гистограммы, KL-дивергенция, метрики).
- [ ] Категориальные признаки закодированы подходящим кодировщиком.
- [ ] Выбросы и дисбаланс классов обработаны.
- [ ] Обучена baseline-модель, чтобы было с чем сравнивать.
- [ ] Каждое действие в ноутбуке обосновано текстом.
